# Experiment 1-B: Grid for Block Placement and Stretching

## Question

Can a non-beginner assemble one staging arrangement in five minutes on a grid with time horizontally and tracks vertically?

## Smallest Components

- 3 tracks and 16 unit cells; no execution engine.
- 5 block kinds (dialogue, camera, sound, animation, wait) used only as placement labels.
- Blocks have `start` and `length` in unit cells, matching the placement vocabulary of 1-A.
- Pick a kind, then drag across empty cells to place a block from its start cell to its end cell.
  A click (a drag of zero length) places a one-cell block.
- Drag a block body to move it across tracks and time; snap to unit cells.
- Drag the right edge to stretch or shrink the block; snap to unit cells, minimum length 1.
- Placements that would overlap on a track or leave the time range are rejected.
- Delete or Backspace removes the selected block; Clear all empties the grid.
- Implementation: `src/editor` (React 19.3.1, Zustand 5.0.16, Immer 11.2.9, Vite 8.3.6).
- Entry point: `pnpm dev`.

## Criterion

- The User can assemble one staging arrangement in five minutes.
- Placement and width changes snap to unit cells.
- No two blocks overlap on the same track.
- Blocks can be moved across tracks.

## What Was Confirmed

- `pnpm typecheck`: core and 1-B UI both pass.
- `pnpm test`: 43 tests pass (34 from 1-A, 9 for the 1-B placement model).
- `pnpm build`: production build succeeds.
- The development server serves the page and the entry module with HTTP 200.
- Pending: the five-minute UI criterion requires the User to run `pnpm dev` and try it.
- Pending: re-checking the drag-to-define building gesture after the User's revision request.

## What Was Decided

1. 1-B keeps its own placement model (`src/editor/model.ts`) instead of using the execution engine's types. The experiment explicitly has no execution engine.
2. The UI layer uses React with Zustand and Immer, following `stack.md`.
3. The building gesture is drag-to-define-start-and-end: pointer down on the start cell, drag to the end cell, release to commit. A click places a one-cell block. This replaced the earlier click-to-place-then-resize gesture at the User's request.
4. An invalid move, stretch, or creation is ignored. The block stays at its last valid position, and a previewed creation that would overlap is discarded.
5. Tracks and columns are fixed for the experiment. Adding or removing tracks is not part of the criterion.
6. `vite.config.ts` lives inside `src/editor` so the root Vitest run keeps discovering both the core and the UI tests.
